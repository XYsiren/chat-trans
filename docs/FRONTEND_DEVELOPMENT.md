# AI 文档助手：前端开发文档

## 1. 范围与目标

本文档定义小程序前端的后续开发方案，适用于“AI 内容结构化、公式校验、模板化 Word 导出”功能。当前原型的单页实现将逐步迁移到页面、组件、服务和状态管理清晰分离的结构。

前端目标：用户能完成“输入内容 → 查看结构 → 处理 AI 建议 → 选择模板 → 导出”的闭环；任意 AI 修改都必须可见、可拒绝、可撤销。

## 2. 信息架构与页面路由

```text
首页 / 草稿列表
  ├─ 新建文档 → 编辑器
  └─ 打开草稿 → 编辑器

编辑器
  ├─ 内容编辑 Tab
  ├─ 结构预览 Tab
  ├─ 问题检查抽屉
  └─ 下一步 → 模板选择

模板选择
  └─ 开始导出 → 导出结果

导出结果
  ├─ 下载 Word
  ├─ 返回编辑器
  └─ 新建文档
```

建议新增以下页面：

| 页面路径 | 页面职责 | 入口 |
|---|---|---|
| `pages/drafts/index` | 草稿列表、新建、删除草稿 | 首页 |
| `pages/editor/index` | 文本编辑、解析预览、问题处理 | 草稿列表/新建 |
| `pages/template-select/index` | 模板选择、导出选项配置 | 编辑器 |
| `pages/export-result/index` | 导出状态、下载与返回编辑 | 模板选择 |

初版可以保留现有 `pages/ai-word/index` 作为迁移入口，但新功能不得继续堆叠在该页面中。

## 4. 页面开发说明

### 4.1 草稿列表页

**展示内容**：新建文档按钮、最近编辑的草稿卡片、文档标题、模板、更新时间、导出状态。

**交互规则**：

- 点击卡片进入编辑器，传递 `draftId`；
- 长按或更多菜单提供重命名、复制、删除；
- 删除前二次确认，成功后刷新列表；
- 首次进入无草稿时展示空态和“新建文档”。

**接口状态**：首屏需区分 `loading`、`empty`、`error` 和 `ready`，禁止在请求未完成时将空数组直接显示成“暂无草稿”。

### 4.2 编辑器页

编辑器采用两个主 Tab：`编辑` 与 `预览`；底部固定主操作按钮根据状态显示“开始解析”“检查问题”或“下一步”。

#### 编辑 Tab

- 提供大文本输入区，显示当前字符数和上限；
- 输入停止 800ms 后触发本地草稿自动保存，不自动请求 AI；
- 用户点击“识别结构”后才解析并更新 `blocks`；
- 输入在解析后改变时显示“内容已修改，请重新识别”，并禁用导出；
- 输入区下方提供支持格式示例，不把复杂规则藏在帮助页中。

#### 预览 Tab

- 按块类型渲染文档，不使用未经清洗的 HTML；
- 公式渲染失败时必须降级显示原始 LaTeX 和“去修复”按钮；
- 点击块内容可跳转至编辑 Tab 并定位源文本范围；
- 顶部展示健康度摘要，如“2 个错误，3 个提醒”，点击打开问题面板；
- 不展示未确认的 AI 建议结果，避免用户误以为已经应用。

### 4.3 模板选择页

模板卡片展示名称、适用场景、封面预览和关键格式信息。选中模板后展示本模板的配置项，例如是否生成封面、是否显示公式编号。

页面底部按钮为“生成 Word”。若存在错误级问题，弹窗说明风险，提供“返回修复”和“仍要导出”；不能静默拦截或静默放行。

### 4.4 导出结果页

导出过程状态机：`idle → submitting → generating → success | failed`。

- `submitting/generating`：显示加载动画、文案和取消返回能力；
- `success`：显示文件名、创建时间、下载按钮、返回编辑按钮；
- `failed`：显示用户可理解的原因、重试和返回编辑按钮；
- 下载完成后提示“已保存到本地”，同时保留再次下载入口。

## 5. 组件开发说明

### 5.1 `document-block`

输入：`block`、`readonly`、`issueCount`。输出事件：`tap`、`edit`。

内部根据 `block.type` 路由到标题、段落、列表、引用、代码、表格或公式子组件。不要在父页面中使用长串 `wx:if` 重复每一种块的视图逻辑。

### 5.2 `formula-block`

属性：`latex`、`displayMode`、`issues`、`editable`。状态：`loading`、`rendered`、`renderError`、`plainText`。

渲染优先级：已验证 LaTeX → 渲染结果；渲染失败 → 原始文本 + 错误提示；无公式内容 → 空态。公式组件不负责调用 AI，只负责通过 `fix` 事件让页面打开对应问题卡。

### 5.3 `issue-card` 与 `issue-panel`

单条卡片必须显示：问题等级、所属块类型、问题描述、修改前后对比、修改理由、置信度、接受/忽略操作。

`accept` 和 `reject` 事件只上抛 `issueId`；真正修改文档内容只能由页面 Store 执行。这样可保证修改记录完整，并防止组件绕过版本管理。

### 5.4 `template-card`

属性：`template`、`selected`、`disabled`。选择模板只改变 `templateId`，不得修改 `blocks`；预览图片加载失败时使用本地占位图。

## 6. 前端状态设计

### 6.1 文档状态

`draft-store` 管理单个当前草稿，建议状态如下：

```js
{
  draft: null,
  sourceDirty: false,       // 原文改变但未重新解析
  parseState: 'idle',       // idle | parsing | success | failed
  reviewState: 'idle',      // idle | reviewing | success | failed
  saveState: 'idle',        // idle | saving | saved | failed
  activeTab: 'edit',
  focusedBlockId: null,
  lastError: null
}
```

状态约束：

- `sourceDirty === true` 时，不允许开始导出；
- `parseState === parsing` 或 `reviewState === reviewing` 时，防止同类请求重复提交；
- 草稿切换前如存在未保存内容，应触发保存或明确提醒；
- 从 AI 建议接受的改动必须使 `updatedAt`、`revision` 更新。

### 6.2 乐观更新边界

以下操作可乐观更新：切换 Tab、选择模板、展开问题卡、写入本地缓存。

以下操作不得乐观标记成功：云端保存、AI 审校、生成 Word、删除云端草稿。它们必须等待接口成功再更新最终状态；失败后保留本地编辑内容和可重试入口。

## 7. 前端数据契约

### 7.1 解析请求

```js
{
  draftId: 'draft_xxx',
  sourceText: '用户原始文本',
  parserVersion: '1.0'
}
```

### 7.2 AI 审校请求

```js
{
  draftId: 'draft_xxx',
  revision: 8,
  taskTypes: ['formula', 'structure', 'placeholder'],
  blocks: [
    { id: 'block_1', type: 'formula', content: '\\frac{a}{b' }
  ]
}
```

前端应只发送需要审校的字段；不能向服务端上传 `rendered`、页面事件对象、文件临时路径或无关用户信息。

### 7.3 AI 审校响应处理

前端收到结果后，先校验：`revision` 是否仍等于当前草稿版本、`blockId` 是否存在、建议的 `before` 是否匹配当前内容。任一不匹配则丢弃该项并提示“内容已更新，请重新检查”，防止旧建议覆盖新内容。

## 8. 交互细节与异常策略

| 场景 | 前端行为 |
|---|---|
| 输入为空 | 禁止解析，聚焦输入区并提示填写内容 |
| 解析失败 | 保留原始文本和上一次有效预览，提供重试 |
| AI 审校超时 | 停止加载，提示稍后重试，不影响手动编辑与导出 |
| 建议过期 | 不允许接受，提示先重新检查 |
| 网络断开 | 显示网络异常；本地草稿继续保存 |
| 导出失败 | 保留模板和草稿，提供原参数重试 |
| 公式渲染失败 | 显示原始公式，不删除或替换用户内容 |
| 草稿删除失败 | 保留页面数据并提示删除失败 |

所有加载操作必须在 `finally`/`complete` 分支关闭 loading，避免页面永久停留在加载状态。

## 9. 样式与可用性规范

- 使用 `rpx` 作为布局单位，文字最小不低于 24rpx；
- 错误、警告、成功状态不能只靠颜色区分，必须配合图标和文字；
- 公式、代码和长文件名必须支持横向滚动或合理换行，不能撑破页面；
- 危险操作使用二次确认；
- 点击区域不小于 88rpx × 88rpx；
- 所有异步按钮需要禁用态与反馈文案；
- 页面标题、空态插图和按钮文案使用统一的产品名称，不保留“QuickStart”等脚手架文案。

建议在 `styles/tokens.wxss` 中集中定义颜色、圆角、阴影、间距与字号，避免页面里出现大量重复硬编码。

## 10. 性能要求

- 输入内容超过 10,000 字时提示分段处理；
- 解析逻辑超过 200ms 时使用分片或 Worker，避免阻塞输入；
- 长文预览只渲染可视区域附近的块，避免一次性创建大量富文本节点；
- 公式图片/预览结果缓存到本地，缓存 key 包含公式内容哈希与渲染版本；
- 防抖仅用于自动保存、搜索和实时校验，不应用于用户点击“生成 Word”等显式操作。

## 11. 前端测试清单

### 11.1 单元测试

- `parser`：标题、列表、代码、块级/行内公式、异常边界；
- `document-normalizer`：旧版本草稿迁移、非法字段过滤；
- `diff`：新增、删除、替换内容的正确展示；
- Store：接受/拒绝建议、撤销、版本号更新和导出前状态校验。

### 11.2 组件测试

- `formula-block` 对正常公式、空公式、渲染失败的降级展示；
- `issue-card` 操作事件是否携带正确 `issueId`；
- `document-block` 对每种块类型的渲染是否符合预期；
- `template-card` 切换时不修改正文数据。

### 11.3 真机验收

1. 新建草稿，粘贴混合格式内容并完成解析；
2. 退出并重新进入，确认内容恢复；
3. 处理一条公式 AI 建议，检查预览和撤销；
4. 选择模板并在存在警告时继续导出；
5. 下载并打开 Word；
6. 在弱网、断网和接口报错下确认页面仍可返回、编辑和重试。

## 12. 前端开发顺序

1. 建立目录结构、设计 token、统一服务请求封装；
2. 搭建编辑器和 `document-block`，完成完整本地解析/预览；
3. 接入本地与云端草稿保存；
4. 搭建问题面板和规则校验结果展示；
5. 接入 AI 审校、版本校验、接受/忽略/撤销；
6. 完成模板选择、导出状态页和异常重试；
7. 引入公式渲染、长文性能优化和埋点。

每一步均需要保持“无 AI 服务时仍可编辑和导出”的降级能力。
