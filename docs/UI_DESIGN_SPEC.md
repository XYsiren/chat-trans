# AI 文档助手：页面视觉与交互设计规范

## 1. 设计方向

产品应像一件安静、可靠的文档工具，而非“聊天机器人”或“炫技 AI 应用”。视觉关键词为：纸张感、秩序、克制、可校对。

- 不使用紫蓝渐变、流光背景、宇宙/大脑/机器人插图；
- 不把“AI”作为页面的视觉主角，仅在需要解释自动建议时使用“智能检查”；
- 以内容和任务状态为主，留白多、边框轻、颜色少；
- 公式、标题和排版预览要像文档本身，而不是卡片堆叠。

## 2. 全局视觉基础

### 2.1 颜色

| Token | 色值 | 用途 |
|---|---:|---|
| `--canvas` | `#F5F5F2` | 应用整体底色，微暖灰 |
| `--surface` | `#FFFFFF` | 卡片、输入区、底部操作栏 |
| `--ink` | `#242424` | 主文字 |
| `--ink-secondary` | `#6E6E6A` | 次级文字、说明 |
| `--line` | `#E7E7E2` | 分割线、默认边框 |
| `--brand` | `#285943` | 主要操作、选中态；深橄榄绿 |
| `--brand-weak` | `#E8F0EA` | 选中背景 |
| `--warning` | `#A76716` | 警告 |
| `--warning-weak` | `#FFF4DF` | 警告背景 |
| `--danger` | `#B64035` | 错误、删除 |
| `--danger-weak` | `#FCEBE8` | 错误背景 |
| `--code` | `#F2F3F0` | 代码区背景 |

主色只用于明确的主操作、选中和少量状态标识；不要用满屏绿色。

### 2.2 字体与字号

- 正文优先系统字体：`PingFang SC, Microsoft YaHei, sans-serif`；
- 代码：`SFMono-Regular, Consolas, monospace`；
- 公式跟随渲染引擎字体，不使用装饰字体。

| 场景 | 字号 | 字重 | 行高 |
|---|---:|---:|---:|
| 页面标题 | 40rpx | 600 | 1.3 |
| 区块标题 | 32rpx | 600 | 1.4 |
| 正文 | 28rpx | 400 | 1.65 |
| 辅助说明 | 24rpx | 400 | 1.5 |
| 按钮文字 | 28rpx | 500 | 1 |
| 文档预览正文 | 30rpx | 400 | 1.8 |

### 2.3 间距、边角与阴影

- 页面左右安全边距：32rpx；
- 常用间距：12 / 16 / 24 / 32 / 48rpx；
- 常规容器圆角：16rpx；输入区与纸张预览：12rpx；
- 默认不投影。底部固定操作栏可用非常浅的 `0 0 20rpx rgba(0,0,0,.05)`；
- 用分割线和留白划分信息，不用密集卡片套卡片。

### 2.4 通用控件

**主按钮**：深绿底、白字、圆角 12rpx、高 88rpx；按下时背景加深，不使用缩放动画。  
**次按钮**：白底、1rpx 浅灰边框、深色字。  
**文字按钮**：无底色，使用主色；危险动作使用红色。  
**标签**：浅色底 + 深色字，圆角 8rpx；只表达状态，不做胶囊式装饰。  
**图标**：线性单色图标，16–20px 视觉大小，优先搭配文字；不使用机器人、魔法棒或闪电图标作为常规入口。

## 3. 全局框架

### 3.1 顶部导航

白色或与底色同色，高度遵循小程序导航规范。左侧返回，中间页面标题，右侧仅保留一个与当前页面强相关的操作，例如“保存”或“更多”。

不要在导航栏放产品 Slogan、AI 徽章或多个图标按钮。标题示例：`我的文档`、`编辑文档`、`选择版式`、`导出完成`。

### 3.2 底部操作栏

适用于编辑器、模板选择页。白色固定在底部，顶部细分割线，内边距 24rpx 32rpx，安全区适配。

主操作占满可用宽度；如果有次操作，使用“左侧文字按钮 + 右侧主按钮”的布局。不可在一个操作栏中放置三枚以上同级按钮。

## 4. 页面一：我的文档（草稿列表）

### 4.1 页面结构

```text
导航栏：我的文档                              [···]
页面内容
  问候/说明：把零散内容整理成一份好读的文档
  [ + 新建文档 ]
  最近编辑
  ─────────────────────────────────
  文档卡片：标题 / 类型 / 更新时间 / 状态
  文档卡片
```

顶部说明只出现一次，正文为“把零散内容整理成一份好读的文档”，避免“让 AI 帮你……”式营销文案。

### 4.2 新建入口

在说明下方放一枚全宽主按钮：`+ 新建文档`。按钮下方不附加“AI 一键生成”等副标题。

### 4.3 草稿卡片

使用白色平面列表行而非大圆角营销卡：

- 标题一行，超长省略；
- 第二行显示模板类型，例如“课程作业 · 2 小时前”；
- 右侧显示轻量状态，如“未导出”“已导出”；
- 行高不低于 132rpx，项目间以 1rpx 分割线隔开；
- 左侧可以使用细色条（深绿/灰），不使用缩略封面图。

滑动操作只提供“重命名”“删除”，删除使用红色文字，避免过度强调。

### 4.4 空状态

使用一张简洁的纸张线稿或仅使用排版符号，不使用 AI 插画。文案：`还没有文档` / `新建一份内容，稍后可以继续编辑。` 下方提供次级按钮“新建文档”。

## 5. 页面二：编辑文档

这是核心页。页面视觉应接近“写作软件 + 校对工具”。

### 5.1 顶部区域

```text
[返回]  编辑文档                          [保存]
文档标题（可编辑）
最后保存于 刚刚                    [课程作业 ▾]
```

标题放在页面内容区，而不是占用导航栏。模板以低调的文本下拉展示，不做醒目卡片。

### 5.2 模式切换

使用纯文本分段控件，而不是大面积 Tab：

```text
编辑        预览
━━━━        ────
```

选中项以深色文字和 4rpx 底部短线表示；不使用亮色胶囊背景。

### 5.3 编辑模式

```text
支持标题、列表、代码和 LaTeX 公式
┌────────────────────────────────────┐
│ 在这里粘贴或输入内容…               │
│                                    │
│                                    │
└────────────────────────────────────┘
8,240 / 10,000

[载入示例] [清空]
```

- 输入区为白色纸张面，边框 `#E7E7E2`，最小高度约 720rpx；
- 聚焦时边框变为主色，背景不变；
- 支持格式说明为普通灰字，不能制作成多彩图标宫格；
- `清空` 仅为文字按钮，且点击后弹出确认框；
- 字数置于输入区下方右侧，小字号灰色。

底部主按钮：未解析时为“识别内容结构”，解析后且原文已改动时为“重新识别”。

### 5.4 预览模式

预览区模拟一张白色文稿，而不是每个块各放一张卡：

```text
┌────────────────────────────────────┐
│ 一、实验原理                         │
│                                      │
│ 这是正文内容……                       │
│                                      │
│              E = mc²                 │
│                                      │
│ 1. 第一个步骤                         │
└────────────────────────────────────┘
```

- 文稿边缘距离屏幕 32rpx，内部边距 40rpx；
- 标题、正文、公式、代码通过排版区分，而不是大色块；
- 代码块用浅灰底和等宽字体；
- 引用块使用左侧 4rpx 灰绿竖线；
- 公式居中；发现问题时在公式右侧添加小型琥珀色圆点，而不是红框包围整段；
- 点击块时出现轻边框和“编辑此处”浮层，不要永久展示编辑图标。

### 5.5 问题摘要与底部操作

预览顶部只放一行收起式摘要：

```text
! 发现 2 个需要确认的问题                         查看
```

没有问题时不展示“健康度 100 分”之类的显眼成绩单，只显示绿色小勾与“内容检查完成”。

底部左侧为“检查内容”，右侧主按钮为“选择版式”。当原文未重新识别时，右侧按钮置灰，并显示原因提示。

## 6. 页面三：问题检查（底部抽屉）

问题检查应作为编辑器上的底部抽屉，而不是跳转到独立页面，方便用户在看上下文时处理。

### 6.1 抽屉结构

```text
──────────────  拖拽条  ──────────────
内容检查                                   [关闭]
2 个需要处理 · 3 个提醒

[需要处理 2]  [提醒 3]

公式格式可能不完整                    公式
原内容  \frac{a}{b
建议    \frac{a}{b}
缺少右花括号                           置信度较高
[忽略]                              [采用]
────────────────────────────────────
```

### 6.2 样式规则

- 错误使用浅红背景条 + 深红文字，不整张卡片铺红；
- 警告使用浅黄背景条 + 深褐文字；
- 原内容与建议内容使用双栏/上下对照，等宽字体，底色分别为灰与浅绿；
- “采用”使用主按钮，“忽略”使用文字按钮；
- 未经用户采用的建议不得改变预览稿内容；
- 置信度不显示精确百分比，转为“较高 / 一般 / 较低”，避免伪精确感。

### 6.3 空状态

显示：`暂未发现需要处理的问题`。不加庆祝动画、撒花或 AI 夸赞语。

## 7. 页面四：选择版式

页面核心是帮助用户选择交付形式，不是展示华丽模板商城。

### 7.1 页面结构

```text
选择版式
根据用途设置文档的排版方式

课程作业                                    已选
适合日常作业与课程报告
────────────────────────────────────
实验报告
带封面和固定章节结构
────────────────────────────────────
学术笔记
适合整理阅读与学习内容

导出选项
□ 添加封面
□ 显示公式编号
```

### 7.2 模板卡片

使用列表式选择行：左侧为模板名称和一句说明，右侧为单选圆点。被选中时仅改变圆点、标题色和左侧 4rpx 细色条；不要使用大幅模板预览图或横向轮播。

“导出选项”置于列表下方，以标准复选框展示。用户勾选后，在底部按钮上显示明确动作：`生成 Word 文档`。

### 7.3 风险提示

若有未修复错误，在按钮上方用小型浅黄提示条说明：`仍有 2 个公式问题未处理，导出后请自行核对。` 提供“返回检查”文字链接。

## 8. 页面五：导出结果

### 8.1 生成中

使用简洁的圆形进度指示器和文字：`正在整理文档…`。下方仅给出阶段提示，例如“正在应用课程作业版式”。不显示假进度百分比，也不显示“AI 正在思考”。

### 8.2 成功状态

```text
              ✓
文档已生成
课程作业_2026-10-10.docx
生成于 今天 14:20

[下载到本地]
返回编辑
```

成功图标使用深绿色线性对勾，不用满屏彩带。文件名为信息主体；下载按钮为唯一主按钮，“返回编辑”为文字按钮。

### 8.3 失败状态

```text
              !
暂时无法生成文档
网络连接不稳定，请稍后重试。

[重新生成]
返回编辑
```

错误信息优先给出用户可执行的说明；技术错误码只在“查看详情”中折叠展示。禁止使用“AI 出错了”等拟人化文案。

## 9. 动效与反馈

- 页面切换使用系统默认转场；
- Tab 切换仅移动底部短线，时长 180–220ms；
- 抽屉使用 240ms 上滑；
- 接受建议后建议内容淡入文稿并展示“已采用”，无粒子或闪烁效果；
- 加载动画仅用于网络等待，静态内容不使用骨架屏泛滥；
- 所有动效需支持系统“减少动态效果”偏好时降级为无动画。

## 10. 前端落地清单

1. 新增 `styles/tokens.wxss` 并将上述 token 写成 CSS 变量或统一常量；
2. 先实现草稿列表、编辑器和底部操作栏三类基础布局；
3. 用 `document-block` 输出纸张式预览；
4. 实现问题抽屉和建议对照，后接入 AI 接口；
5. 实现列表式模板选择和导出结果状态；
6. 以真机为准检查长文本、长公式、深色模式（如支持）和小屏设备。

## 11. 禁止项

- 不使用“AI 帮你一键完成”“魔法生成”等夸张文案；
- 不使用大面积渐变、玻璃拟态、漂浮粒子或机器人插画；
- 不将每一段文档内容都包装成独立圆角卡片；
- 不用红/绿颜色单独表达问题状态；
- 不让加载、建议或导出结果阻断用户返回编辑；
- 不让 AI 自动覆盖原始内容或隐藏其修改痕迹。
